中文摘要
主数据取自提交包内的设计团队自评估（Algorithm Specifications.pdf §5.1，即本仓库 hash-33-spec.pdf 第 40–43 页）：performance-optimized 实现、官方 ngcc_bench S1–S8 消息长度（32 B–64 KiB）、单核，两个平台（Intel Xeon Platinum 8358 @ 2.60 GHz 与 Rockchip RK3588）。长消息下 Thunder-512 在 x86-64 达 6.95 cycles/byte（ARM 7.62），低于同表 SHA3-512 （12.46 / 15.49），并在 x86-64 上全程快于 SM3(256)。注意：自评估只覆盖三个定长实例，XOF 不在其中。 ngcc.dev 对 reference 实现（未优化）的独立测量保留在本页下方作对照，两者不可直接比较。

† The SHA3-512 and SM3 baselines are portable software implementations that do not use the Armv8.2 SHA3 / SM3 instruction extensions (spec Table 19 footnotes). Per the spec: Thunder-512 and Thunder-768 stay below SHA3-512 at every tested length on both platforms; on x86-64 Thunder-512 is faster than SM3(256) at all lengths (6.95 vs 8.45 cpb at S8). The spec also reports ≈74 measured cycles per round on ARM against a ≈75 design-level estimate (spec p. 41). The XOF instances are not covered by the software self-assessment.

Hardware (spec §5.2, Table 20)

ASIC implementations (UMC 55 nm, round-based) are reported in Table 20. Per the spec, Thunder-512 reduces the cycle count of SHA3-512 by 32% / 49% / 50% at 32 B / 1 KiB / 64 KiB and improves the throughput-to-area ratio by 13% / 16% at 1 KiB / 64 KiB; Thunder-768 and Thunder-1024 improve long-message throughput over SHA3-512 by 51% and 43% respectively — spec pp. 44.

Independent reference-implementation check (ngcc.dev)

Separately from the submission package, ngcc.dev measured the reference implementation (unoptimized placeholder-quality code) on its own x86_1 system. These numbers characterize the reference code, not the design’s optimized speed, and are not comparable with the self-assessment tables above; they are kept here as an independent correctness-and-timing cross-check.
