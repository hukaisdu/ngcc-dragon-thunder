中文摘要
Thunder 是 NGCC Round 1 的 hash 候选（编号 hash-33）。与 Dragon 同用 sponge-forward 模式（capacity 部分每次置换后前馈 XOR 回去，(second-)preimage 安全性 ≈ min{c, h}，digest 直接从 inner 部分读出），但置换不同：Thunder-p 是 Keccak-p 形状的 1600-bit (5×5×64) 置换，12 轮，非线性层 ψ 是 3 次的（Keccak 的 χ 是 2 次），θ 用双列校验。 共六个实例：Thunder-512/768/1024 与 Thunder-XOF-256/384/512。 本站汇总其规范、参考实现、KAT、性能与第三方分析，素材镜像自 ngcc.dev 与 NICCS（2026-10-30）。

Quick facts

itemvalue
modesponge-with-feed-forward Sponge-F^{P,pd10*} (Guo et al., CRYPTO 2026, per the spec ref [GHJ+25]) — digest is squeezed from the inner (capacity) part; a final-block constant C prevents length extension
permutationThunder-p: 12-round, Keccak-p-shaped 1600-bit (5×5×64) permutation, round R = ψ ∘ π ∘ θ ∘ ρ ∘ ι, with degree-3 ψ and double-column-parity θ
instancesThunder-512 / -768 / -1024 (fixed-output hash) and Thunder-XOF-256 / -384 / -512 (XOF)
claimed securitycollision 256/384/512 bits, preimage 512/768/1024 bits (fixed instances); XOF: min{level, ν/2} / min{level, ν}
KAT6/6 instances PASS (ngcc.dev harness, x86_1 campaign 2026-09-25 → 09-28)
implementation reviewno parameter or constant mismatch found; output-length domain separation verified via three independent mechanisms
speed (designer self-assessment)6.95 cycles/byte @ 64 KiB on x86-64 (Intel Xeon Platinum 8358), 7.62 on RK3588 — below SHA3-512 at every tested length, faster than SM3 on x86-64 (spec §5.1, Tables 18–19)
speed (independent check)reference implementation (unoptimized): 32.4 cycles/byte @ 64 KiB (ngcc.dev x86_1) — see Performance
