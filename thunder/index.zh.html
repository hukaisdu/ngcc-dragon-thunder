Thunder 杂凑家族NGCC Round-1 杂凑候选 hash-33 · symmetric（permutation-based）

NGCC Round 1 hash-33 自测向量 6/6 通过 暂无公开漏洞发现*
太长不看：Thunder = Keccak-p 骨架的 12 轮置换 Thunder-p（三次非线性层 ψ、双列校验 θ）+ sponge-forward 前馈模式，六个实例。软件上 Thunder-512/768 全长度快于 SHA3-512（512 长消息约 1.8×，ARM 约 2.0×）；硬件吞吐全面高于 SHA3-512（64 KiB 最高 +82%）。安全目标最高 512-bit collision / 1024-bit preimage。

Thunder 与 Dragon 同用 sponge-forward 模式（capacity 部分每次置换后前馈回加， (second-)preimage 安全性 ≈ min{c, h}，digest 直接从 inner 部分读出），但置换不同： Thunder-p 是 Keccak-p 形状的 1600-bit（5×5×64）置换，12 轮，非线性层 ψ 是 3 次的（Keccak 的 χ 是 2 次），θ 采用双列校验。全族共六个实例：Thunder-512/768/1024 与 Thunder-XOF-256/384/512。本站汇总其规范、参考实现、KAT、性能与第三方分析；素材镜像自 ngcc.dev 与 NICCS（2026-10-30），数字已对照 spec LaTeX 源核验。

速览

条目内容
模式 (mode)sponge-with-feed-forward Sponge-F^{P,pd10*}（Guo, Hu, Jiang, Fan, Fu, Preneel, Wang — ePrint 2025/1006，发表于 CRYPTO 2026）— digest 从 inner（capacity）部分直接读出；final-block 常数 C 防长度扩展
置换Thunder-p：12 轮、Keccak-p 形状的 1600-bit（5×5×64）置换，轮函数 R = ψ ∘ π ∘ θ ∘ ρ ∘ ι，其中 ψ 为 3 次、θ 为双列校验
实例Thunder-512 / -768 / -1024（定长输出）与 Thunder-XOF-256 / -384 / -512（XOF）
安全目标collision 256/384/512 bit、preimage 512/768/1024 bit（定长实例）；XOF 为 min{等级, ν/2} / min{等级, ν}
自测向量（KAT）6/6 实例通过（KAT = Known-Answer Test，已知答案测试——对提交的“输入 → 期望输出”向量对答案；ngcc.dev harness，测量期 2026-09-25 → 09-28）
实现核对未发现参数或常数不吻合；输出长度间的 domain separation 经三条独立机制确认
速度（设计团队自评估）长消息比 SHA3-512 快约 1.8×（x86-64：6.95 vs 12.46 cpb）、约 2.0×（ARM：7.62 vs 15.49）；x86-64 上 Thunder-512 全程快于 SM3（6.95 vs 8.45）（spec §5.1，Tables 18–19）
