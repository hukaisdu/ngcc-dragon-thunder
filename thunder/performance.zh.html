性能提交包内的设计团队自评估

主数据取自提交包内的设计团队自评估（spec §5.1，第 40–43 页，数字已对照 LaTeX 源逐格核验）： performance-optimized 实现、官方 ngcc_bench、S1–S8 消息长度（32 B–64 KiB）、单核， 两个平台（Intel Xeon Platinum 8358 @ 2.60 GHz 与 Rockchip RK3588）。长消息下 Thunder-512 在 x86-64 达 6.95 cycles/byte（SHA3-512 为 12.46，约 1.8 倍加速）、ARM 上 7.62（SHA3 为 15.49，约 2.0 倍）；Thunder-512/768 在全部测试长度上均快于 SHA3-512；x86-64 上 Thunder-512 全程快于 SM3(256)。 硬件综合（Table 20）三个实例吞吐全部高于 SHA3-512（64 KiB：+82% / +51% / +33%）。 注意：软件自评估只覆盖三个定长实例，XOF 不在其中。

一句话结论：软件——Thunder-512/768 在全部测试长度快于 SHA3-512（512 长消息 6.95 vs 12.46 cpb，约 1.8×；ARM 7.62 vs 15.49，约 2.0×）；x86-64 上 Thunder-512 全程快于 SM3（6.95 vs 8.45）。硬件——三个实例吞吐全面高于 SHA3-512（64 KiB：+82% / +51% / +33%）。
读表提示：cpb = cycles/byte，越低越快；S1–S8 = 消息长度 32 B → 64 KiB。

Round-based 架构（每周期一轮），VHDL + ModelSim 验证，Synopsys Design Compiler 综合。 数值已对照 LaTeX 源核验。依据 spec：Thunder-512 把 SHA3-512 的周期数削减 32% / 49% / 50% （32 B / 1 KiB / 64 KiB），尽管 critical path 略长（0.93 vs 0.84 ns），吞吐仍提升 32% / 77% / 82%； 其 TP/Area 仅在 32 B 低于 SHA3-512，1 KiB / 64 KiB 反超 13% / 16%。Thunder-768 与 Thunder-1024 在三个长度上吞吐均高于 SHA3-512（64 KiB 分别 +51% / +33%） （spec 第 44 页）。
