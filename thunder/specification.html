All bit lengths. Message limit 2⁶⁴ bits. Fixed instances use c = h + 64 — the feed-forward mode allows this instead of the classical c ≥ 2h.

XOF naming trap. As with Dragon, Thunder-XOF-256/384/512 name a security level, not an output length. The harness exposes the XOFs through the fixed-length CryptHash API at exactly one squeeze block (1280/1152/1024 bits = 160/144/128 bytes). Note r′ > c for the XOFs (e.g. 1280 > 576): a squeeze block spans the whole inner part plus part of the outer part, which the feed-forward mode permits (spec §2.5). These three fixed lengths are not separate hash functions — shorter outputs are prefixes of longer ones.

Mode: sponge-with-feed-forward (spec §2.2, Fig. 2)

The same Sponge-F^{P,pd10*} construction as Dragon (Guo, Hu, Jiang, Fan, Fu, Preneel, Wang — ePrint 2025/1006, published at CRYPTO 2026): the inner (capacity) part is fed forward across every permutation call, and the digest is squeezed from the inner part. Because the output is the inner part, the final-block constant C = 0^{c−1}‖1 is what prevents length extension.

Thunder-h(M):                             # h in {512,768,1024}, c = h+64
    X <- 0^r || IV                        # IV_j -> lane j
    Mpad <- M || 1 || 0^{r-((|M|+1) mod r)}   # pd10*
    for i = 1..l:                          # absorb
        X <- X XOR (M[i] || (i==l ? C : 0))
        S <- right_c(X)                    # inner part AFTER the xor
        X <- P(X) XOR (0^r || S)           # feed-forward
    return right_h(X)                      # h < c: one read, no extra permutation

Permutation Thunder-p (spec §2.3, Tables 2–4)

12 rounds of R = ψ ∘ π ∘ θ ∘ ρ ∘ ι on the 1600-bit 5×5×64 state — the Keccak-p lane geometry and five-step structure, but in the order ι → ρ → θ → π → ψ (Keccak-p: θ → ρ → π → χ → ι):

  • ψ (for Keccak’s χ) is degree 3: D'[x][y] = D[x][y+3] ⊕ ( ¬D[x][y+1] · D[x][y+2] · ¬D[x][y+4] ), indices in Z₅.
  • θ mixes two column parities P and Q (offsets t = (41, 50, 6, 10, 27), u = 26, r = 1, s = 36) instead of Keccak’s single parity.

Lane layout and serialization follow the spec: message words big-endian into the highest-indexed rate lanes (M_{n_r−1} into lane 24), digest D_{n_d−1} ‖ … ‖ D_0, MSB-first per lane.
