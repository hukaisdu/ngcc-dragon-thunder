Dragon ↗ Thunder ↗ EN

术语表本站出现的术语，简明中文解释（术语保留英文）

术语解释
sponge（海绵结构）一种构造 hash 的模式：消息按块写入状态（absorb），再从状态读出输出（squeeze）。SHA3 就是 sponge。
sponge-forward（前馈 sponge）Dragon/Thunder 用的模式：每次置换前保存 capacity 部分、置换后 XOR 回去。把 preimage 安全性从 c/2 提升到约 min{c, h}（ideal-permutation 模型下），因此 c = h + 64 就够（经典 sponge 要 c ≥ 2h）。见 ePrint 2025/1006。
permutation（置换）对固定长度比特串的可逆变换，这里是 1600-bit 状态上的多轮变换（Dragon-p 16 轮 ARX；Thunder-p 12 轮 Keccak-p 形状）。
capacity（c）/ rate（r）sponge 状态的两部分：r 是每块吸收/挤出的比特数，c 是内部“安全余量”，r + c = 1600。c 越大越安全、越慢。
absorb / squeeze吸收：消息块 XOR 进状态再过置换；挤出：从状态读出输出比特。XOF 的多次挤出即“要多少给多少”。
XOFextendable-output function，可变长输出函数：输出长度 ν 由调用者指定（对照定长 digest 的 hash）。
digest杂凑值（输出）。Thunder-512 即输出 512 bit。
collision / (second-)preimage两类攻击目标：找碰撞（两消息同 digest）/ 找原像（给定 digest 找消息）。设计目标：collision ≈ h/2 bit、preimage ≈ h bit。
log₂QXOF 实例的 generic 安全等级：攻击者做 Q 次置换询问时的优势界。XOF-256 的 256 是这个等级，不是输出长度。
cpb（cycles/byte）每字节数据耗费的 CPU 周期数，越低越快。S1–S8 指自评估规定的消息长度 32 B → 64 KiB。
KATKnown-Answer Test，已知答案测试：提交包给出一组“输入 → 期望输出”向量，实现对答案，全对说明实现与规范一致。
reference / optimized 实现提交包含多档实现：reference 是可读的规范直译（慢），optimized 面向性能。性能页的两套数字分别来自这两档（及不同机器），不可直接比较。
constant-time（常数时间）代码执行时间/访存地址不依赖秘密数据，是抵抗时序侧信道的必要条件。
domain separation（域分离）让不同用途/长度的输入产生不可混淆的内部状态。两族均采用每实例不同的 IV + 最后块常数 C = 0^{c−1}‖1（C 区分末块与非末块、防长度扩展）。共享 capacity 的实例对之间仅靠不同 IV 分离。
lane1600-bit 状态 = 5×5 个 64-bit 字，每个字叫一条 lane。
ARX模加（Addition）、循环移位（Rotation）、异或（XOR）三类指令构成的变换——Dragon-p 的全部运算。
pd10* padding填充规则：消息后补一个 1 再补 0 到块边界（多零块情形见规范页）。
kGE / TP/Area硬件指标：千门等效面积（kGE）；吞吐除以面积（TP/Area），越高越省面积。
