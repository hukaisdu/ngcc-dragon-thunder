性能提交包内的设计团队自评估

主数据取自提交包内的设计团队自评估（spec §5.1，第 33–35 页，数字已对照 LaTeX 源逐格核验）： performance-optimized 实现、官方 ngcc_bench、S1–S8 消息长度（32 B–64 KiB）、单核， 两个平台（Intel Xeon Platinum 8358 @ 2.60 GHz 与 Rockchip RK3588 @ 2.0 GHz）。长消息下 Dragon-512 在 x86-64 达 4.87 cycles/byte（SHA3-512 为 12.46，约 2.6 倍加速）。硬件综合（Table 16）中 三个实例的综合频率为 251–258 MHz（ARX 进位链限制，critical path 3.88–3.98 ns），当前吞吐低于 SHA3-512。注意：软件自评估只覆盖三个定长实例，XOF 不在其中。

一句话结论：软件——三个定长实例在两个平台的全部测试长度上均快于 SHA3-512（Dragon-512 长消息 4.87 vs 12.46 cpb，约 2.6×；ARM 4.47 vs 15.49，约 3.5×）；Dragon-512/768 还全长度快于 SM3。硬件——第一版综合（251–258 MHz）吞吐低于 SHA3-512，但周期数最多少 1.8×、功耗约为一半。
读表提示：cpb = cycles/byte，越低越快；S1–S8 = 消息长度 32 B → 64 KiB。

Round-based 架构（每周期一轮），VHDL + ModelSim 验证，Synopsys Design Compiler 综合。 数值已对照 LaTeX 源核验。本次提交版本的综合结果中，三个 Dragon 实例只能在 251–258 MHz 收敛 （critical path 3.88–3.98 ns，受 ARX 进位链限制），因此吞吐低于 1190 MHz 综合的 SHA3-512 基线； 1 KiB / 64 KiB 的周期数更少（最多 1.8 倍），功耗约为其一半 （spec 第 35 页）。
