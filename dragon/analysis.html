Security status

No vulnerability finding is currently published for this candidate (ngcc.dev security report, snapshot 2026-10-28). This records only the present state of the public finding inventory and is not a security endorsement; the candidate remains under review.

Constant-time audit (ngcc.dev)

Scope: archived reference implementation, fixed digest parameters and fixed message length; message contents and intermediate state treated as secret. Two source points examined:

  • Reference entry: Dragon-ARM/…/Reference_Implementation/Dragon-1024/CryptHash_AlgorithmInstance.c:94.
  • The XOF helper copy_bits_msb branches in C on each squeezed output bit (Dragon-x86/…/Dragon-XOF-256/CryptHash_AlgorithmInstance.c:101), but GCC -O2 compiles the branch to cmovne in the inspected x86 reference variant.

Status: no issue promoted — no data-dependent machine branch or address was observed. Full text: mirrored audit page · live.

Implementation-vs-specification review

No deviation from the specification was found. Round constants, rotation offsets (1, 10, 24, 33, 49), lane mapping (M_i → lane 25−n_r+i), pd10* padding with the final-block constant C, the feed-forward X ← P(X) ⊕ (0^r ‖ right_c(X)) and the digest order D_{n_d−1} ‖ … ‖ D_0 all agree with the spec. Not re-verified by ngcc.dev: the full IV tables of four instances (two 9-lane tables were checked entry-by-entry) and the SM3-counter derivation of the IVs; the mode’s security proof (§4.1) and the permutation cryptanalysis (§4.2). Details: pseudocode.md.

Notes worth remembering

  • XOF naming trap: the number in Dragon-XOF-* is a security level (log₂Q), not an output length; the fixed one-shot digest is one squeeze block (1280/1152/1024 bits) — see Specification.
  • CryptHash() (fixed instances) ignores digest_len_bits: smaller values overflow the output buffer, larger ones are silently truncated.
  • IV transparency: Dragon's IVs come with an explicit SM3 counter-mode derivation program in the spec (ngcc.dev has not recomputed it). Contrast: Thunder's IVs state no derivation rule at all — a transparency gap there, a checkable claim here.
  • Related: “Chinese NGCC Algorithms: The First Week of AI Cryptanalysis”, IACR ePrint 2026/2266 — a survey of the first week of AI-assisted cryptanalysis across all 119 NGCC Round-1 candidates (191 published findings, 78 rated critical). It reports no finding for Dragon, consistent with the ngcc.dev inventory.
