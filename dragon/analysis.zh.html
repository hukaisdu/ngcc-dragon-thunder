分析第三方状态、constant-time 审查、核对注记

截至 ngcc.dev 2026-10-28 快照，Dragon 没有已公开的 vulnerability finding （ngcc.dev security 报告）。这只是公开 finding 清单的当前状态，不是安全性背书；该候选仍在评审中。

Constant-time 审查（ngcc.dev）

范围：归档的 reference 实现、固定 digest 参数与固定消息长度；消息内容与中间状态视为秘密。 审查了两个源码点：

  • Reference 入口：Dragon-ARM/…/Reference_Implementation/Dragon-1024/CryptHash_AlgorithmInstance.c:94。
  • XOF 的 copy_bits_msb 辅助函数在 C 源码里对每个输出 bit 分支 （Dragon-x86/…/Dragon-XOF-256/CryptHash_AlgorithmInstance.c:101）， 但在受检的 x86 reference 变体中 GCC -O2 把该分支编译成 cmovne。

结论：未升级为问题——未观察到依赖数据的机器分支或地址。全文： 镜像审查页 · 线上。

实现与规范核对

未发现与规范的偏差。轮常数、rotation offsets (1, 10, 24, 33, 49)、lane 映射 （M_i → lane 25−n_r+i）、pd10* padding 与 final-block 常数 C、前馈 X ← P(X) ⊕ (0^r ‖ right_c(X))、digest 顺序 D_{n_d−1} ‖ … ‖ D_0 均与 spec 一致。ngcc.dev 未复核的部分：四个实例的完整 IV 表（两张 9-lane 表已逐项核对）、 IV 的 SM3 counter 导出重算、模式安全证明（§4.1）与置换密码分析（§4.2）。 细节：pseudocode.md。

值得记住的几点

  • XOF 命名陷阱：Dragon-XOF-* 中的数字是安全等级（log₂Q）而非输出长度； 一次性固定 digest 是一个 squeeze block（1280/1152/1024 bit）——见 规范页。
  • CryptHash()（定长实例）忽略 digest_len_bits：更小的值会溢出输出缓冲区， 更大的值被静默截断。
  • IV 透明度：Dragon 的 IV 在 spec 中有明文的 SM3 counter-mode 导出程序（ngcc.dev 尚未重算）。 对比：Thunder 的 IV 完全没有给出导出规则——那边是透明度缺口， 这边是可核查的声明。
  • 相关文献：“Chinese NGCC Algorithms: The First Week of AI Cryptanalysis”， IACR ePrint 2026/2266——覆盖全部 119 个 NGCC Round-1 候选的首周 AI 辅助分析综述（191 项公开 finding，78 项 Critical）；文中对 Dragon 未报告 finding， 与 ngcc.dev 公开清单一致。
