中文摘要
主数据取自提交包内的设计团队自评估（Algorithm specifications.pdf §5.1，即本仓库 hash-07-spec.pdf 第 33–35 页）：performance-optimized 实现、官方 ngcc_bench S1–S8 消息长度（32 B–64 KiB）、单核，两个平台（Intel Xeon Platinum 8358 @ 2.60 GHz 与 Rockchip RK3588）。长消息下 Dragon-512 在 x86-64 达 4.87 cycles/byte，低于同表 SHA3-512（12.46）与 SM3 （8.45）。注意：自评估只覆盖三个定长实例，XOF 不在其中。ngcc.dev 对 reference 实现 （未优化）的独立测量保留在本页下方作对照，两者不可直接比较。

† The SHA3-512 and SM3 baselines are portable software implementations that do not use the Armv8.2 SHA3 / SM3 instruction extensions (spec Table 15 footnotes). All three Dragon instances stay below both baselines at every tested length on both platforms. The spec also reports that the measured optimized x86 implementation costs ≈38.8 cycles per permutation round (design estimate ≈40, spec p. 33). The XOF instances are not covered by the software self-assessment.

Hardware (spec §5.2, Table 16)

The three fixed-output instances are also implemented in VHDL and synthesized for ASIC (UMC 55 nm, round-based architecture, one round per clock cycle); Table 16 reports area, delay, frequency, power, cycle count, throughput and throughput-to-area ratio for 32 B / 1 KiB / 64 KiB messages — spec p. 35.

Independent reference-implementation check (ngcc.dev)

Separately from the submission package, ngcc.dev measured the reference implementation (unoptimized placeholder-quality code) on its own x86_1 system. These numbers characterize the reference code, not the design’s optimized speed, and are not comparable with the self-assessment tables above; they are kept here as an independent correctness-and-timing cross-check.
